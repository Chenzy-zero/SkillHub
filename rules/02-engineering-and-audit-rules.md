# 工程与审计规则

本文件维护跨模块的工程、安全和审计细则。

## 1. Digest 计算

`skill_digest` 必须覆盖完整 Skill Package，推荐流程如下：

1. 遍历纳管文件并使用规范化相对路径排序；
2. 对每个文件计算 SHA-256；
3. 将相对路径、文件哈希和需要保留的文件模式组成规范清单；
4. 对规范清单再次计算 SHA-256。

实现必须明确并测试换行符、Unicode 路径、可执行位、符号链接、Git LFS、二进制文件和忽略规则。
不得使用时间戳或 MD5 判断内容是否一致。

## 2. 幂等与一致性

- 事件、批量任务和扫描任务必须使用稳定任务键，重复执行不得产生冲突记录。
- Source Revision 不可覆盖；相同 Digest 不重复创建 Content Version。
- Rename 和 Delete 同时记录旧路径与新状态，不能只处理当前路径。
- 扫描期间出现新提交时，保留旧版本结果，但不得推进最新版本状态。
- 扫描、审核和 SkillHub 同步分别保存状态、错误和重试记录。
- 配置、输入、策略或扫描器版本变化时，不得在同一批次静默混用。

## 3. 扫描与安全边界

- 扫描结果必须记录扫描器名称、版本、策略版本、内容 Digest、来源 Revision 和执行时间。
- 公司治理结论不得仅依据单一扫描器的通过字段。
- 默认不执行、不导入、不编译、不安装被审查 Skill 中的内容或依赖。
- 远程访问只允许访问任务明确配置的只读代码服务和批准的软件源。
- 路径逃逸、符号链接越界、归档异常、输出冲突和清理目标不明确时必须停止任务。
- 私钥、密码、Token、环境变量值和完整秘密不得进入日志、报告、提交或 AI 上下文。

## 4. 证据与审计

- 关键状态变化必须记录操作者、时间、对象、原状态、新状态和原因。
- 原始扫描证据与面向使用者的派生报告分开保存；对外报告只提供必要的脱敏信息和证据索引。
- 清理只允许由受信程序执行，并且不得删除仍被未完成任务引用的输入、状态或证据。
- 失败和例外必须保留可恢复状态，不得通过删除批次或覆盖结果“修复”。
- Canonical Skill 的关联和拆分、结论复用、人工例外和发布状态变化必须可追溯。

## 5. 变更与验证

- 修改数据模型、Digest、状态或复用规则时，必须增加相应的回归测试和迁移说明。
- 修改跨平台入口时，同时验证 Windows `.cmd` 与 Unix `.sh` 的路径和编码行为。
- 修改正式方案时只描述当前有效设计；实施顺序放入计划文件，调研和废弃选择留在历史材料中。
